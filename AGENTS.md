# Правила проекта

## Контекст

Этот файл хранит постоянные договорённости по проекту сайта. Обновляй его, когда появляются важные решения, ограничения или предпочтения.

## Рабочий процесс

- Перед изменениями изучать текущую структуру проекта и существующий код.
- Сохранять важные решения и требования в этом файле или в `idea.md`.
- После изменений проверять результат доступными тестами и сборкой.
- Не удалять и не перезаписывать пользовательские файлы без явной необходимости.

## Требования проекта

- Статический личный каталог AI-инструментов без backend.
- Dark by default, минималистичный technical/product UI без чрезмерных градиентов, blur и glassmorphism.
- Данные инструментов хранятся отдельно в `data/tools.json`; карточки и detail view строятся из объектов данных.
- Поддерживаются поиск, категории, фильтры по цене и платформе, избранное и localStorage.
- Читаемые ссылки реализованы через hash routes (`#/tools/<id>`, `#/category/<id>`), чтобы прямые переходы работали на GitHub Pages.
- Проект не требует build step и не добавляет зависимости без причины.
- Не добавлять демонстрационные инструменты или выдуманные данные: каталог заполняется только пользователем.
- `data/tools.json` — единственная публичная canonical database. Интерфейс не сохраняет опубликованные инструменты в `localStorage`.
- Публичные предложения создаются через GitHub Issue Form и проходят schema/duplicate validation; label `approved` создаёт PR, но не делает merge автоматически.
- `localStorage` допустим только для избранного, темы, UI-предпочтений и черновиков.
- Цена инструмента может быть только `free`, `mid` или `expensive`.
- Основной публичный CTA — «Предложить инструмент»: Quick Add, Manual и AI JSON Import готовят submission, а не изменяют каталог. Полный owner-import выполняет локальная команда `npm run add-tool -- <url>` и только после подтверждения обновляет `data/tools.json`.
- Не имитировать браузерный импорт внешних страниц через CORS-прокси: GitHub Pages должен оставаться полностью статичным и устойчивым.
- `data/tool-schema.json` — единый источник структуры для AI Prompt Builder, валидации JSON Import и enum-значений. Prompt требует чистый JSON, не допускает выдуманных значений и всегда оставляет `notes` пустым.

## Принятые решения

- Первая версия сделана на обычных HTML/CSS/ES modules без framework.
- `index.html` — shell приложения, `styles.css` — дизайн и responsive layout, `app.js` — состояние и UI, `data/tools.json` — каталог.
- Если цена, команды или возможности неизвестны, поле остаётся пустым до уточнения.
- Тема, избранное и пользовательские настройки сохраняются в `localStorage` браузера.
- Для локального запуска используется `python -m http.server 8080` или аналогичный простой статический сервер.
