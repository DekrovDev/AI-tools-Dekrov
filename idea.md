# Идея сайта

Вставь сюда большой промпт и любые дополнительные требования к сайту.

## Открытые вопросы

- Целевая аудитория
- Основная задача сайта
- Предпочтительный стиль и визуальные референсы
- Технологии и способ публикации
Хочу начать новый личный проект.

Сделай мне полноценный сайт-каталог всех AI-инструментов, которыми я пользуюсь, тестирую или хочу сохранить на будущее.

Смысл сайта:
я постоянно нахожу новые AI-сервисы, coding agents, CLI, desktop-приложения, модели и полезные инструменты, а потом забываю названия, ссылки, команды установки и для чего конкретно они мне были нужны.

Этот сайт должен стать моей личной AI-базой / AI toolbox.

В будущем я хочу разместить его через GitHub Pages, вероятно на поддомене ai.dekrov.com, поэтому первая версия должна быть полностью статической и нормально работать без backend.

ВАЖНО:
не делай очередной шаблонный AI-сайт с огромными градиентами, glowing-карточками, бесконечным glassmorphism и надписями вроде "Unlock the power of AI".
Мне нужен нормальный современный продуктовый интерфейс.

Стиль:
- dark by default;
- минималистичный;
- чистый;
- современный;
- немного technical/developer vibe;
- хорошая типографика;
- аккуратная иерархия;
- приятные микроанимации;
- не перегруженный;
- ощущение нормального инструмента, которым хочется пользоваться каждый день.

Если в проекте доступен skill human-ui-designer — используй его принципы.

==============================
ОСНОВНАЯ СТРУКТУРА
==============================

Главная страница должна давать быстрый доступ ко всей базе.

Наверху:
- название проекта;
- короткое описание;
- глобальный поиск;
- быстрые фильтры;
- переключатель темы, если считаешь уместным.

Основные категории примерно такие:

1. Coding Agents
2. Chat / LLM
3. Research
4. Image
5. Video
6. Audio
7. Dev Tools
8. Hosting / Infrastructure
9. Other

Не обязательно визуально делать их обычными огромными секциями.
Продумай удобную структуру сам.

==============================

- название;
- короткое описание;
- официальный URL;
- категория;
- теги;
- статус;
- доступные платформы;
- цена / Free / Freemium / Paid;
- моя личная заметка;
- установка;
- команда запуска;
- дополнительные команды;
- модели, если это AI-клиент;
- кнопка открытия сайта;
- кнопка копирования команды;
- кнопка открытия подробной страницы.

Пример статусов:

- Active
- Testing
- Saved
- Archived

Пример тегов:

- coding
- agent
- free
- cli
- desktop
- web
- vscode
- open-source
- research
- image

Платформы:

- Web
- Desktop
- CLI
- VS Code
- API

==============================
ДАННЫЕ
==============================

Не хардкодь десятки карточек прямо в HTML.

Вынеси данные инструментов отдельно.

Например:

data/tools.json

или другую разумную статическую структуру.

Хочу в будущем иметь возможность добавить новый инструмент, изменив буквально один объект данных.

Структуру данных продумай нормально заранее.

Примерно:

{
  "id": "freebuff",
  "name": "Freebuff",
  "category": "coding-agents",
  "description": "...",
  "url": "https://freebuff.com",
  "platforms": ["desktop", "cli", "web"],
  "pricing": "free",
  "status": "active",
  "tags": ["coding", "agent", "free", "cli"],
  "install": "npm install -g freebuff",
  "start": "freebuff",
  "notes": "...",
  "models": [...]
}

Не обязан повторять эту структуру буквально.
Если можешь спроектировать лучше — сделай лучше.

==============================
ПОИСК И ФИЛЬТРЫ
==============================

Это одна из главных функций сайта.

Нужен быстрый клиентский поиск.

Он должен искать хотя бы по:

- названию;
- описанию;
- тегам;
- категории;
- платформе;
- заметкам.

Фильтры:

- категория;
- статус;
- Free / Paid / Freemium;
- Web / Desktop / CLI / VS Code;
- возможно теги.

Не превращай интерфейс в панель управления Boeing.
Фильтрация должна оставаться простой.

Сделай возможность быстро сбросить фильтры.

==============================
UX
==============================

Особенно продумай:

- удобство ежедневного использования;
- быстрый поиск;
- keyboard focus;
- hover / active / disabled states;
- пустые состояния;
- отсутствие результатов поиска;
- копирование команды с feedback;
- responsive;
- мобильную версию;
- нормальный sidebar/navigation на desktop;
- нормальную навигацию на mobile;
- длинные команды;
- длинные названия;
- много тегов;
- отсутствие некоторых данных у инструмента.

Добавь маленькие детали, которые реально улучшают использование.

Например:
- Cmd/Ctrl + K для поиска;
- Escape закрывает поиск/модалки;
- copy feedback;
- количество найденных инструментов;
- favorites;
- recently used, если это можно адекватно сделать локально;
- сохранение пользовательских настроек в localStorage.

Но не добавляй фичи просто ради количества.

==============================
ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ
==============================

Главное:
сайт должен легко размещаться на GitHub Pages.

Не добавляй backend.

Можно использовать:
- HTML/CSS/JS;
или
- современный статический frontend stack, если он реально оправдан.

Если выбираешь framework/build system:
- объясни выбор;
- убедись, что deployment на GitHub Pages простой;
- не создавай тяжёлую архитектуру для маленького проекта.

Проект должен:
- нормально запускаться локально;
- иметь понятную структуру;
- иметь README;
- иметь инструкции запуска;
- быть responsive;
- не выдавать ошибок в console;
- не ломаться при прямой работе через GitHub Pages.

Не используй зависимости без причины.

==============================
ВАЖНО ПРО ДИЗАЙН
==============================

Не копируй буквально Linear, Vercel, GitHub или Cursor.

Можно ориентироваться на качество таких продуктов, но дизайн должен иметь собственный характер.

Не используй:
- emoji вместо нормальных UI-иконок повсюду;
- случайные градиенты;
- огромные hero-секции;
- бессмысленные маркетинговые тексты;
- 25 разных цветов;
- карточки внутри карточек внутри карточек;
- слишком много border-radius;
- чрезмерный blur;
- слишком маленький серый текст.

Сайт в первую очередь инструмент, а уже потом showcase.

==============================
ПЕРВАЯ ИТЕРАЦИЯ
==============================

Сначала:

1. Осмотри текущую папку проекта.
2. Спроектируй архитектуру.
3. Определи структуру данных.
4. Определи дизайн-систему.
5. Реализуй полноценную первую версию.
6. Запусти её.
7. Проверь ошибки.
8. Проверь responsive.
9. Проведи собственный критический review.
10. Исправь очевидные проблемы, которые найдёшь.

Не останавливайся после создания каркаса.

Мне нужна рабочая первая версия, которую я смогу открыть и реально начать использовать.

Не задавай мне вопросы по мелочам.
Если решение не критично — прими разумное решение самостоятельно.

Если существует несколько хороших вариантов — выбери тот, который считаешь лучшим, и реализуй.

Начинай.
